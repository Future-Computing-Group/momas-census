# Citation links between the literatures (Fig. 2b; Supplementary Note 3)

Four runs, all on OpenAlex, retrieved 2026-11-09, with no email or key in any request (asserted in `oa.py`).

- `run1-learning/`: seven literatures that hold results on learners (performative prediction, multi-agent RL, learning in games, cooperative AI, ML-system feedback loops, economics of learning, system identification), with the algorithmic-fairness baseline.
- `run2-eleven/`: the same plus mechanism design, distributed computing, law and political science.
- `run3-dc/`: run 2 with distributed computing (R2) broadened from Byzantine and rational fault tolerance to the chapters of van Steen and Tanenbaum, Distributed Systems, 4th ed. (2023): the seven run-2 seeds plus eleven classics for architectures, processes, communication, coordination, naming, consistency and replication, and security (`seeds.py`, appended at the end). Run-2 R2 kept as the sensitivity case. Objectives check outputs, all sixteen variants, old and new: `crossmap/`. `layers.py` iterates seeds sorted when picking a literature's dominant subfield (C5 is a tie that hash order resolved in run 2; no link is affected).
- `run4-broad/`: run 3 with four more literatures broadened by the tables of contents of reference works: economics of the rules (R1; Viscusi, Harrington and Sappington, 5th ed., and Mas-Colell, Whinston and Green, chs 14 and 23), control (C7; Åström and Murray, 2nd ed., Ljung, 2nd ed., Borkar 2008), law (R3; Oxford Handbook of Law, Regulation and Technology, Restatement (Third) of Agency, competition law) and political science (R4; Oxford Handbooks of Regulation and of AI Governance). 37 added seeds (12, 14, 5, 6), kept in `seeds.py` as `ADDED` with group "run4"; `fetch.py` fetches only the added seeds' citers and takes the union with the cached pools. Run 3 is the narrow sensitivity case (`crossmap/old` is run 3's `crossmap/new`). `layers.py` also reports the per-field question for C7; `c7_loo.py` leaves one control seed out at a time and recomputes the system-identification seeds alone. `render_si_note3.py` renders the Supplementary Note 3 table files from `data/bibliometric.json` into a given folder with the formatting of `si_tables.py`. `probe_broad.py` was the seed-candidate probe.

Data: the raw OpenAlex responses and the corpora are archived in `data/raw/openalex-fields-2026-11-09.tar.gz` (runs 1-2) and `data/raw/openalex-dc-2026-11-09.tar.gz` (run 3: the 90 new responses and its `works.json`, under `biblio-dc/`) and `data/raw/openalex-broad-2026-11-09.tar.gz` (run 4: the 285 new responses and its `works.json`, under `biblio-broad/`); sha256 in `data/raw-archives-sha256.txt`; the archives are not in the repository. Results: `data/fields/` (results.json and results_m1.json from run 1, results_m1-eleven.json, results_layers.json and seeds.json from run 2; run 3: results_m1-eleven-dcbroad.json, results_layers-dcbroad.json, seeds-dcbroad.json; run 4: results_m1-eleven-broad.json, results_layers-broad.json, results_c7_loo-broad.json, seeds-broad.json).

To reproduce without network calls: extract the archive; in a working folder put the run's scripts, its `works.json`, its `seeds.json` and a link `raw` to `biblio2/raw` from the archive (it holds both runs' responses); run `python3 -s -E analyse.py` (run 1, then `extra.py`) or `python3 -s -E analyse.py m1` then `layers.py` (run 2). Do not use `python3 -I`, which drops the script's folder from the import path. Reproduced on 2026-11-09: results files identical, zero network calls. Run 3: extract both archives, link every file of `biblio2/raw` and `biblio-dc/raw` into one `raw/`, copy `run3-dc/*.py`, `seeds-dcbroad.json` as `seeds.json` and run 1's `results.json`; `fetch.py` rebuilds `works.json` byte-identical from the cache, then `analyse.py m1`, `layers.py` and the sixteen `crossmap.py` variants reproduce the stored files byte-identically with zero network calls (checked 2026-11-09 with the proxy pointed at a closed port). Run 4: extract all three archives, link every file of `biblio2/raw`, `biblio-dc/raw` and `biblio-broad/raw` into one `raw/`, copy `run4-broad/*.py`, `seeds-broad.json` as `seeds.json` and run 1's `results.json`; `fetch.py` rebuilds `works.json` byte-identical, and `analyse.py m1`, `layers.py`, `c7_loo.py` and the sixteen `crossmap.py` variants reproduce the stored files byte-identically with zero network calls (checked 2026-11-09, proxy at a closed port; the printed call counter reads 2 network calls on the original run, 0 on reproduction).

The sub-question check (Supplementary Note 3): the units are the 25 sub-questions of Box 2 in `data/fields/subquestions.json`; two blind coders judged, for each sub-question and each of the eleven literatures, whether a seed of the literature holds a result the sub-question uses (`codebook-needs.md`). `run4-broad/needs_inputs.py` fetched the seeds' abstracts (three cached filter calls, no email or key; `data/fields/seeds-broad-abstracts.json`, raw responses in `data/raw/openalex-abstracts-2026-11-10.tar.gz`, sha256 in `data/fields/needs-manifest.json`) and built one batch per coder (`data/batches/needs-c1.json`, `needs-c2.json`; literatures under codes L01 to L11 assigned at random per coder, keys in `data/fields/needs-keys.json`, which the coders were not given). `run4-broad/crossmap.py` validates the coded files (`data/coded/needs-c1.jsonl`, `needs-c2.jsonl`), forms need sets under the both-coders and either-coder rules and runs the sixteen link variants on the run-4 links and, with each yes restricted to run-3 seeds, on the run-3 links (`crossmap/{both,either,earlier-both,earlier-either}/`); a variant whose links leave no pair of literatures below its threshold is set aside. `crossmap/new` and `crossmap/old` hold the earlier check, which matched author names over the cross-field ledger's objectives. The print figure is `../fig_census_fieldmap.py`.
